## Summary

- **Salary** (`src/features/salary/`, `staff_finance.read`; replaces the "Salary — coming" item)
  - **Month view** `/salary?month=&group=` (default: previous month): one row per staff member employed in the month,
    status chip in words (Not calculated · Saved vN · **Changed since saved** · Needs manual resolution), saved payable
    and — managers only — "Payable now", days (saved snapshot, else the live numbers), unmarked count, "Partial month".
    Totals from the server. Phones get cards. **CSV** of saved results only (a live preview is never exported).
  - **Calculator** `/salary/:staffId?month=`: the server's numbers (salary, working, attended, paid leave, unpaid,
    deduction, payable) and the **formula with real values** ("₹40,000.00 × (15 + 1) / 20 = ₹32,000.00"), marked days
    (2410 `marked_days`: present / late / half day / absent + unmarked), unmarked dates and discrepancies in plain words,
    each linking to the staff register for that date. **Overrides** (working / attended / paid leave in 0.5 steps,
    salary in rupees → paise by string math) are validated like the server, need a reason, are **previewed** with
    `preview_salary`, and Save sends exactly the previewed values; the server's field errors show under the field.
    "Needs manual resolution" is explained and blocks Save until the required override is given.
    Save: "Saved as version N" / **"Already saved — no new version"** (replay). A saved version's overrides refill the
    form, so an unchanged re-save replays.
  - **Paid leave**: add (full / half day, optional reason, the server's `note` shown), cancel (with confirmation;
    CONFLICT = already cancelled), cancelled ones collapsed. **Saved versions** with Final / Superseded, who and when.
  - Readers (Owner): the saved result, status and history; no calculator, no buttons, no `preview_salary` calls.
- **Reports**
  - **Attendance register** `/attendance/register?section=&month=`: desktop grid students × dates — day-wise
    P / L / H / A, **blank = not marked** (tinted, "Not marked" for screen readers; never "A"), period-wise
    "attended/held" with `*` when some lessons are unmarked, "—" when the student wasn't in the section, non-working
    days greyed with their label, per-student totals with **Provisional / Final**. **Phones**: one card per student
    with the month summary; tapping opens the per-day list. CSV (words, never blanks). Class teachers open it from
    Today ("Month register"); the server answers FORBIDDEN for anyone else and that is shown.
  - **Attendance changes** `/attendance/changes`: Students / Staff tabs (capability-driven), old → new in words,
    actor and role, time; section filter; click a name to see only that person; keyset Load more.
  - **Academic coverage** `/reports/coverage` (`academic.read_all`, new nav item): ≤ 63 days, sort, "only rows that
    need attention", Unassigned rows kept, diary x / y, homework due fully checked / with no checks, period attendance
    marked (labelled "at least one mark"), totals = sum of rows shown, CSV.
  - **Fee-head totals** `/fees/reports/heads` (a tab in the fee area): per head gross / concession / adjustments /
    net, adjustments without a head, charged / paid / balance, the server's note, a reconciliation line, CSV.
- **Lessons on a date (TIME-02)**: "Change time" in the lesson actions (version sent; overlap refusals shown as sent;
  a past lesson may change — owner decision); **"Add extra lesson"** on the schedule (section, date, times, subject of
  the class, optional teacher / label / reason). DUPLICATE → "Already added" + **Open it**; an uncertain failure
  re-sends the same request (DUPLICATE then means the first attempt worked). Badges **Extra lesson** / **Changed for
  this date** from 2410 `source` on the schedule and on Today. "Teacher absent, not covered" filter (`?uncovered=1`,
  2410 `actual_teacher_absent`).
- **Dashboards** (`get_dashboard`, one call): the page renders exactly the blocks the server returns — Admin all,
  Principal attendance / staff / academic (+ Academic coverage and Register shortcuts), Accountant fees (+ Collect,
  Day book, Dues, Cheques), Owner attendance / fees / salary. Teacher keeps Today, parents the child home. Every number
  links to the page that counts it the same way (table below). Setup issues link to the page that fixes them,
  grouped with a count when there are many. Loading / error / offline never show 0.
- **Operator console** (`/operator/activity|sign-ins|usage|maintenance`, Operator accounts — the server checks the
  live grant): activity log (school / username / action prefix / record / IST dates; actor name + username + role,
  via-Operator, expandable redacted detail), sign-ins & sessions (failed sign-ins without an account say so; "last
  seen is not a sign-out time"), usage (labelled estimates), maintenance (retention, "Daily at 02:30 IST", runs,
  **Run now** with confirmation). "Operator console" in the navigation; the "Coming soon" list is now empty.
- **Expired sessions**: an app session the server ended (e.g. the daily job after 30 idle days) makes
  `bootstrap_account` answer UNAUTHENTICATED; the app now signs out of Auth locally with "Your session has ended.
  Please sign in again." (unit test; previously it signed out with no message).

## Brief ↔ database mismatches and observations (no backend changes made)

Items 1–6 of the plan review were resolved by migration 2410. Still open:

0. **`get_salary_month` can exceed the 8 s statement timeout** (`authenticated` role: `statement_timeout=8s`). Full
   run 4 failed on it (HTTP 500 "canceling statement due to statement timeout", from the spec's API read; the page
   calls the same RPC). Measured (read-only `EXPLAIN ANALYZE`): one `compute_salary` pass over Demo School's 47 staff
   for a month = **1.31 s** (~28 ms per staff member: a `resolve_day` + two lookups per day). Since 2410,
   `get_salary_month` computes every row live and again with the saved overrides for saved rows — up to ~2.6 s warm for
   Demo, more under load, and it grows with staff count. The UI shows "Could not load this" + Try again (never ₹0), and
   the spec was **not** given a retry (it would hide this). Suggest (backend): resolve the staff calendar once per
   group and month instead of per staff and day, and skip the second compute when the saved version has no overrides.
1. **"Changed since saved" can be followed by "Already saved — no new version".** 2410 marks a row `changed` when the
   unmarked days differ from the saved version, but `save_salary_calculation` replays whenever the numbers are equal
   (it doesn't compare unmarked days). Seen live: paid leave moved from one unmarked day to another → "Changed since
   saved" → Save → "Already saved". Correct money-wise, confusing to read. Options: let the replay also compare
   `unmarked_working_dates` (a new version that records them), or don't count unmarked-only differences as `changed`.
2. **No idempotency / version on salary and leave saves** (as planned): `save_salary_calculation` relies on the
   content replay; `record_paid_leave` on the per-day DUPLICATE; `cancel_paid_leave` has no version (CONFLICT = already
   cancelled, shown as such).
3. **The register lists dates only up to today**; a day the student wasn't in the section has no cell ("—"). Coverage
   "period attendance marked" = lessons with at least one mark (labelled).
4. **Extra lessons take slot numbers 20, 19, …, and cancelled lessons keep theirs**, so a section/date allows ~12 extra
   lessons in total (then LIMIT_REACHED). The live spec reuses one extra lesson on 19 Oct so it doesn't use them up.
5. **An Operator whose app session ended gets FORBIDDEN from `op_*`** (`require_operator` checks the session), not
   UNAUTHENTICATED. A reload goes through `bootstrap_account` first and signs them out cleanly; only an operator page
   left open through the expiry shows "no access" until reloaded.
6. **The activity log also holds generic row events** (`salary_calculations.insert` / `.update`, …) beside the named
   ones (`salary.calculation.saved`); listed as stored. `operator.retention_cleanup` events have no school, so a school
   filter hides them.
7. `op_get_usage` sessions: at most 200, no paging, no school per row (labelled on the page).

## Design notes

- **Money and days**: amounts are paise from the server, shown with `MoneyText` ("—" / "Not saved" / "Can't
  calculate" when missing, never ₹0); typed rupees → paise with `parseRupeesToPaise`; days parsed from the text in 0.5
  steps and shown with `formatDays`; the deduction is integer paise. The formula is built from the server's numbers —
  the client never computes a salary.
- **Save = what is on screen**: overrides are previewed first; Save is disabled while the form differs from the
  preview, while the preview refreshes, or when it can't be calculated.
- **Confidential**: salary queries have their own `salary-*` keys in the memory-only, context-scoped cache; the Owner
  never calls `preview_salary`; the CSV has saved results only; salary nav and routes need `staff_finance.read`.
- **Shared helpers**: `src/lib/csv.ts` (`toCsv`, `downloadCsv`; the fee CSV uses it now), `parseMonthParam` /
  `monthParam` in `src/lib/dates.ts`, `MonthPicker` (previous / next month in words, same on every browser).
- **Refresh**: student / staff marks, lesson changes, diary, homework checks and money mutations also invalidate the
  register, change trail, coverage, salary, fee-head report and dashboard.
- **Operator console gating**: by the account's Operator flag (the server's own rule); `audit.read` exists only inside
  a school context.
- **Setup issues**: grouped per kind with a count; "Show sections" lists each with its own link.
