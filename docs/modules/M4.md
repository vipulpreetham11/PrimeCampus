## Build
### 1. Salary (`src/features/salary/`) — replaces the "Salary" upcoming nav item
- **Month view**: month picker (default: previous month) + staff group filter → `get_salary_month(month, group?)`.
  Table/cards per staff: status chip (Not calculated · Saved vN · **Changed since saved** · Needs manual resolution),
  saved payable vs live payable (managers), working / attended / paid leave / unpaid days, unmarked count,
  partial-month flag. Totals row = saved payable sum. Owner sees saved results only (`can_manage` false).
- **Staff detail / calculator** (`preview_salary` → `save_salary_calculation`): show salary, working days,
  present/half-days, paid leave, unpaid days, deductions and the formula with real numbers
  ("₹40,000 × (15 + 1) / 20 = ₹32,000"); list `unmarked_working_dates` and `discrepancies` in plain words
  (map each `issue` code to a sentence) with links to the staff attendance register for those dates.
  Overrides (working / attended / paid leave days in 0.5 steps, monthly salary in rupees → paise) need a reason;
  show the server's field errors under the field. `needs_manual_resolution` → explain `resolution_reason` and
  require overrides. Save: a repeat with nothing changed returns `replayed: true` (say "Already saved — no new
  version"). History: `get_salary_calculations(month, staff)` with versions (final / superseded) and who/when.
- **Paid leave** (`record_paid_leave`, `cancel_paid_leave`, `list_paid_leave(from, to, staff?)`): add full/half day
  with reason from the staff detail; show the server's `note` (overlap with present attendance).
- **Export**: CSV of the month view (saved rows; amounts as rupees with 2 decimals) for `staff_finance.read`.
  Confidential: never shown or exported to other roles.

### 2. Reports
- **Attendance register** (`src/features/attendance/register`): section + month → `get_attendance_register`.
  Grid students × dates; day-wise cells P / L / H / A / **blank = unmarked** (not absent); period-wise cells
  "attended/held" with marked < held shown as incomplete; non-working days greyed with their label; per-student
  totals with **Provisional** when not final. Phone: a per-student list with the month summary and a per-day
  drill-down instead of a wide grid. CSV export.
- **Attendance changes** (`list_attendance_changes(from, to, kind, section?, person?)`, keyset): who changed which
  mark, old → new, when, with role; student and staff tabs (staff tab needs `staff_attendance.read`).
- **Academic coverage** for Principal/Admin (`get_academic_coverage(from, to ≤ 63 days, section?)`): per section ·
  subject · teacher — lessons, diary written (x / y), homework set, homework due fully checked / unchecked, period
  attendance marked. Sort/filter; "Unassigned" teacher rows visible. CSV.
- **Fee-head totals** (`get_fee_head_report(year, term?)`, `fees.read`): per head gross, concession, adjustments,
  net; totals row with charged / paid / balance; show the server's `note` (collections are per invoice, not per
  head) and `adjustments_without_head_paise`. CSV. Link it from the M3 reports area.

### 3. Lessons on a date (TIME-02) — `timetable.manage`
- In the M2 day/week view lesson actions: **Change time** → `update_lesson_session(…, 'change_time', …,
  p_start_time, p_end_time)` with the version; show overlap messages; an "override" badge on changed lessons.
- **Add extra lesson** for a section + date (`add_extra_lesson`: start/end, subject from the class, optional teacher,
  label, reason). DUPLICATE (same section/date/start/subject) → "Already added" + open it. Extra lessons show an
  "Extra" badge and behave like any lesson (attendance, diary, homework, substitutes).

### 4. Dashboards — `get_dashboard(date?)` (one call; render only the blocks present)
Replace the role home screens (keep Teacher "Today" and the parent child home from M2):
- **Admin**: attendance marking coverage (sections complete / not started), absent teachers + lessons with an
  absent teacher (link to the day view), diary missing (last 7 days) and unchecked homework, follow-ups
  overdue/today, collections today + dues/overdue + pending cheques + open exceptions, last month's salary status,
  **setup issues** list with links to fix each.
- **Principal**: attendance, staff, academic blocks + link to Academic coverage and the register.
- **Accountant**: fees block + links to Collect payment, Day book, Dues, Cheques.
- **Owner**: fees, salary, attendance summary (read-only).
Each number links to the page that shows the same count with the same rules. Loading/error/offline never show 0.

### 5. Operator console (`src/features/operator/`, `audit.read`) — replaces "Activity logs"
- **Activity log** `op_get_audit_events(school?, actor?, action prefix, entity, from, to, cursor)`: table with
  actor, via-operator flag, school, action, entity, time, compact detail (expand JSON, redacted as stored).
- **Sign-ins & sessions** `op_get_auth_events(...)` and the sessions list from `op_get_usage`.
- **Usage** `op_get_usage(from, to, school?)`: daily active accounts + page views (labelled estimates), logins.
- **Maintenance** `op_get_maintenance()`: retention settings, whether the daily job is scheduled, last runs with
  results; "Run now" → `op_run_retention_cleanup()` (confirm). Sessions idle for 30 days are ended by this job —
  the user simply signs in again (make sure the M0 UNAUTHENTICATED path handles it cleanly).

## Rules
All CLAUDE.md rules. Money as paise; salary days are decimals in 0.5 steps — use string math for display and input.
"Unmarked" / "not calculated" / "no data" are their own states. Exports never include data the role can't see.
Use the M2X/M3 helpers (field errors, OperationTracker where an op id exists, `@/lib/zod`, DataState).
