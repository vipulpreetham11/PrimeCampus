## Build
1. **Scaffold**: Vite + React + TS (strict), Tailwind, shadcn/ui (init + Button, Input, Label, Form, Dialog, DropdownMenu,
   Select, Table, Toast/Sonner, Skeleton, Badge, Card, Sheet), React Router data router with lazy routes, TanStack Query,
   React Hook Form + Zod, supabase-js v2, Vitest + RTL, Playwright, ESLint + Prettier. Scripts: `dev`, `build`, `preview`,
   `typecheck`, `lint`, `test`, `test:e2e`. `.env.example` with the three VITE_ values from CLAUDE.md.
2. **`src/lib`**:
   - `supabase.ts` — single client, publishable key only.
   - `rpc/` — typed wrappers for EVERY function in `public` (generate types or read the migrations). One function per RPC;
     wrappers for school RPCs take the context revision automatically from the context store.
   - `errors.ts` — `AppError {code, message, requestId}` mapped from `error.hint` per CLAUDE.md rule 3; global handlers for
     `UNAUTHENTICATED` and `STALE_CONTEXT`.
   - `operation.ts` — `useOperationId()` (stable per action, reset after success).
   - `money.ts` (paise↔rupees, en-IN format, string-based parsing) and `dates.ts` (school-local `YYYY-MM-DD`, display formats).
     Unit-test both thoroughly (edge cases: ₹0.05, 1,00,000.50, negative, invalid input, IST midnight).
   - `edge.ts` — caller for the `accounts` Edge Function (`supabase.functions.invoke('accounts', {body})`), typed per action.
3. **Auth & context (TRD §6–§7)**:
   - Sign-in page: username + password → alias email login → `bootstrap_account`. Generic error on failure (never reveal
     whether a username exists).
   - Forced change-password page when `must_change_password` (calls Edge `change_password`); nothing else reachable.
   - Context chooser: lists contexts from bootstrap (e.g. "Teacher — School A", "Parent — School A"); parents with several
     children get child cards (name, class-section). Single context enters directly. Operator gets a school picker.
   - Context store (React context or Zustand-free plain module + hook): holds revision, role, school, child, capabilities
     (`get_context`). Switch role/school/child action always visible in the header.
   - Switching / logout: cancel in-flight queries, `queryClient.clear()`, reset forms, BroadcastChannel to other tabs.
     Logout calls `end_app_session` then `auth.signOut()`.
4. **App shell**: header (school name, academic year, role, child, switcher, user menu with change password + logout),
   sidebar/bottom-nav driven by capabilities, responsive at 375px. Placeholder route per role dashboard that says
   "Coming in module Mx" — no fake buttons (PRD §15).
5. **Shared components**: `DataState` (loading skeleton / empty / error with request id / forbidden / offline),
   `MoneyInput`, `MoneyText`, `DateInput` (school-local), `ConfirmDialog`, `OneTimeSecretDialog` (shows a temp password
   once, copy button, cleared on close), `PageHeader`.
6. **Operator onboarding (minimal, needed to test anything)**: Operator-only page to create an organization + school via
   `op_create_school`, then provision that school's first Admin via Edge `provision` (shows temp password once).
7. **Telemetry**: `record_telemetry` page_view batching (≤20 events, flush every 60s and on hide). Best effort, never blocks UI.
8. **Deploy config**: `wrangler.jsonc` for Cloudflare Workers static assets with SPA fallback; `npm run build` output only. Don't deploy.
